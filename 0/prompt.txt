The implementation is a checked native registry around explicit Vulkan operations. Milestone 1 must replace its synchronous completion assumptions while preserving recorded-resource ownership.

1. **Why this shape exists.** [docs/design.md](/home/aivv/Документы/projects/bend-vulkan/docs/design.md:3) explains that Bend permits fabricated ordinary constructors and cannot extend opaque host handles. C therefore owns pointers and dispatch; Bend exposes distinct `Data` handles containing monotonic U32 keys. Affine wrappers alone would neither ensure native destruction nor avoid threading owners through results. Temporary copy-based mapping avoids exposed pointer/cache lifetimes. Registry changes run exclusively on the IO event loop; pure preparation can parallelize.

2. **Normal recording/submission.** In [src/native.c](/home/aivv/Документы/projects/bend-vulkan/src/native.c:635), `bv_begin_command_buffer` accepts only state `0`, requests `ONE_TIME_SUBMIT`, and enters recording `1`. `bv_cmd_fill_buffer` checks ownership, binding, transfer-destination usage, bounds, and four-byte alignment, then records a `BvUse` before calling Vulkan. `bv_end_command_buffer` currently inserts transfer-write→host-read synchronization and enters executable `2`. `bv_submit_and_wait` marks command `3` and device `1` before `QueueSubmit`, then calls `QueueWaitIdle`. Success clears device state; command state remains `3`.

3. **Failure behavior.** Begin/end Vulkan failures set command state `4`; rejected fill arguments leave recording intact. [bv_submit_and_wait](/home/aivv/Документы/projects/bend-vulkan/src/native.c:680) conservatively retains device state after submit/wait errors other than device loss. Buffer/pool destruction, memory freeing, host copies, and further submissions then reject operations. `bv_device_wait_idle` clears that state on success or device loss. Thus device `state` presently means unresolved completion after failure, rather than a complete asynchronous submission model. A failed submission cannot automatically rely on its fence eventually signaling.

4. **References and teardown.** [BvRow/BvUse and destruction helpers](/home/aivv/Документы/projects/bend-vulkan/src/native.c:17) encode `entry→instance→device→pool→command` ownership, plus command→buffer references and buffer→allocation bindings. Completion therefore does not itself make buffers destroyable. [Entry.with/Entry.finish](/home/aivv/Документы/projects/bend-vulkan/Vulkan.bend:226) run cleanup after returned success/failure and preserve the callback error, appending cleanup errors. [bv_entry_close](/home/aivv/Документы/projects/bend-vulkan/src/native.c:221) waits, destroys pools/references, buffers, allocations, devices, instances, then unloads.
